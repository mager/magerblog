OpenClaw rebranded on January 30, 2026. NanoClaw launched January 31.

That's either a shot across the bow or a compliment. Probably both.

The Cohens — Gavriel (ex-Wix) and Lazer — built the original OpenClaw. When OpenClaw pivoted away from its original shape, they didn't follow it. They stripped the concept to its essence and shipped something new under a new name, one day later. [NanoClaw](https://github.com/nanocoai/nanoclaw) is the thing OpenClaw used to be, minus everything that made OpenClaw complicated.

I [killed OpenClaw in June](/blog/2026-06-02-killing-openclaw/) specifically because it ran on Codex, not my Claude Pro subscription. Per-token billing to keep an always-on agent alive didn't make sense when I already had a $20/month subscription sitting there. So I ported everything to `claude --channels` and a `CLAUDE.md`. That held.

But I've been watching NanoClaw. Here's what it actually is.

## The codebase

~700 lines of TypeScript. That's the whole thing.

Not 700 lines of the interesting parts, with another ten thousand lines of scaffolding beneath. The entire framework. You can clone it, find a coffee, read it cover to cover, and still have time to push a fix before the coffee gets cold.

The Anthropic Agents SDK is the foundation — NanoClaw is a thin, opinionated layer on top. It handles the connections (WhatsApp, Telegram, Slack, Discord, Gmail), the memory, and the scheduled jobs. The SDK handles the agent loop. There's no novel architecture to learn. If you've read the Anthropic docs, NanoClaw is immediately legible.

That readability is a deliberate feature, not a side effect of being small. A framework you can audit is a framework you can trust.

## One container per session

This is the part that genuinely impresses me.

Every conversation runs in its own Docker container. When the session ends, the container self-destructs. No shared state between conversations, no lateral blast radius if something goes sideways, no single compromised session affecting the host.

My current setup (`claude --channels` running on a Mac mini) has no sandbox at all. The session runs as me, on my machine, with access to whatever I've given it access to. The allowlist and `CLAUDE.md` keep it reasonably contained, but if the agent does something unexpected, it does it on my actual machine. There's no isolation layer. That tradeoff is fine for my use case — I understand the surface and I control what connects — but it's real.

NanoClaw's container model solves this properly. Isolation is architectural, not behavioral. You're not relying on the agent following instructions to stay contained; you're relying on Docker to enforce the boundary. That's a fundamentally better guarantee.

The self-destruct is equally clean: sessions don't accumulate. No stale state, no zombie containers, no need to clean anything up. Spin up, do the work, gone.

## The honest catch

NanoClaw runs on the Anthropic Agents SDK. The Agents SDK uses API billing — not Pro, not Max, not subscription credits. Per-token.

That's exactly the reason I left OpenClaw.

OpenClaw ran on Codex and billed per token. I switched to `claude --channels` to get off API billing and onto my subscription. If I ran NanoClaw, I'd be back in the same position: an always-on agent that charges me per message, on top of a subscription I'm already paying.

The Cohens built something excellent. The container isolation is better than what I have. The codebase is auditable in a way OpenClaw's never was. Multi-platform support (WhatsApp + Telegram + Slack + Discord + Gmail in one small codebase) is genuinely useful. If I were starting from scratch, I'd probably start here.

But I'm not starting from scratch. I'm on a setup that works and doesn't bill me per inference. Switching to NanoClaw would trade the billing advantage I have for a sandboxing advantage I don't need urgently.

## Who this is actually for

Developers starting fresh who want an agent that can reach users across multiple messaging platforms. NanoClaw is MIT-licensed, the Anthropic API pricing is reasonable at moderate scale, and you get container isolation out of the box without having to roll your own Docker setup.

It's also for people who want to read everything their agent framework does before they trust it. Seven hundred lines. No surprises.

If you're already on `claude --channels` and happy with it, the switch cost is real and the gains are incremental. If you're building something new and need WhatsApp or Discord integration from day one, NanoClaw is probably the right call.

## On simplicity in AI tooling

The landscape right now is full of frameworks that keep adding surface area. Every week something new — new abstraction, new protocol, new graph-based orchestration layer that promises to make everything easier while doubling the things you have to understand. Most of it is entropy dressed as features.

NanoClaw went the other direction. The 700-line count is a signal about priorities: this is a tool built to be understood, not to be impressive. That's increasingly rare, and it's worth paying attention to even if you don't end up using it.

I'll keep watching. If they add a subscription-compatible runtime path, I'll reconsider. Until then: this is what OpenClaw should have been, and I'm rooting for it.

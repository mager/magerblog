I started with a smaller goal: contribute to four more open source projects within a week. I had already made a set of contributions, and I wanted a better way to keep track of them and decide what to work on next.

Then I looked at my own projects. [Homeport](/blog/2026-10-04-homeport/), [Mood Shell](/blog/2026-10-02-mood-shell/), and [Perch](/blog/2026-10-04-perch/) have source code, live sites, and posts explaining how I built them. Those pieces live in different places. A repository shows the code. A blog post explains a decision. Neither gives someone a quick way to browse the software I make and try something useful.

That became [Sidework](https://sidework-ten.vercel.app/mager/), a personal software gallery for discovering projects through the people who build them. **This is the very first version of Sidework.** I am sharing it early, with my own profile and the tools I need to fill it. The design and setup flow are still changing as I use them. The longer-term idea is a social network around projects and contributions.

## Projects and contributions belong together

I want a profile to answer a few practical questions: What does this person build? What does the software do? Can I try it? Where is the source? What have they helped improve elsewhere?

Personal projects and upstream contributions can share a profile while keeping their meaning clear. Homeport is a project I built. A pull request to Impeccable is a contribution to someone else's project. Sidework gives the first a project view with a screenshot, description, stack, and links. The second gets a link to the actual pull request, its repository, and its recorded status.

That distinction matters more to me than an activity total. A useful fix can be small. A project can be useful before it attracts stars. I want the work itself to be easy to inspect, with `@handles` identifying the people behind it.

## From a portfolio page to a software gallery

The first design iterations had large headings, unusual fonts, and generous space around project screenshots. I liked parts of the design, but the page still felt too much like a blog. Changing the type did not change the activity: you were still scrolling through a long presentation.

The public profile now opens into a gallery. Homeport, Mood Shell, Perch, and prxps each have a short description of the task they help with. Category links let visitors narrow the selection. Screenshots keep their original colors against a simple black-and-white interface, and normal links open separate project pages. Selected contributions sit below the gallery.

Each project can also have a category, a software type, an intended audience, and up to five concrete features. Category describes its purpose; software type tells you whether it is a web app, command-line tool, library, or another form of software. Programming languages stay in the stack field. The aim is to explain what someone can do with a project before asking them to inspect the code.

I am keeping that structure small. GitHub supplies repository facts, while the author reviews the description and classification. Unknown details can stay blank. The gallery and category links work without JavaScript; project detail pages currently require an invite.

I built this with Astra and used Impeccable during the interface work. The repeated revisions helped clarify the product: I wanted people to discover a builder through their software, with enough context to decide what to open next.

## Two interfaces, with different jobs

I kept both the public profile and a private workbench. The profile is for visitors. The workbench is where I can import repositories, edit project descriptions, and plan contributions.

The GitHub importer works with public repositories. It loads the repository list across pages, lets me search and filter it, and supports selecting several repositories at once. Reimporting should preserve the descriptions and project order I have already edited.

GitHub supplies useful facts, but a repository description rarely tells the whole story. The editor also has space for why I built something and what I learned. Those fields need my input; they should not become confident guesses based on a README.

My [public profile](https://sidework-ten.vercel.app/mager/) does not require an invite. The rest of the prototype is invite-only while I work through the setup and editing flow.

## Setting up a profile through MCP

I also wanted an agent interface from the start. If I am already working with a coding agent, I should be able to ask it to help prepare my Sidework profile.

The prototype includes a Model Context Protocol (MCP) endpoint at `/api/mcp` and a Claude Code plugin. Tools such as `get_profile`, `list_github_repositories`, and `prepare_profile_draft` let an agent inspect the existing profile, find public repositories, and prepare a draft with up to six projects.

The intended request is simple: “Set up my Sidework profile from my public GitHub repositories.” The agent can gather facts and prepare descriptions, then return a review link. I inspect the result in the browser before saving it. The [agent setup guide](https://github.com/mager/sidework/blob/main/docs/agents.md) covers the connection and plugin installation.

The agent cannot publish to the public profile. Saving an accepted draft currently saves it in that browser. This gives me a way to test assisted setup before connecting it to account ownership and publication.

## What the prototype can do today

Sidework runs on Astro and Vercel. The public profile is a committed snapshot, and changes to that snapshot require a source update and a rebuild. Imports, saved projects, follows, and editing drafts are stored in the browser. There is no shared social graph or cross-device account system yet, and the importer does not access private repositories.

The next useful step is to make one person's complete path work: connect GitHub, choose a few projects, review their descriptions, and publish a profile they can return to and update. After that, I want to test whether browsing other people's projects actually helps someone find useful software or a contribution they want to make.
